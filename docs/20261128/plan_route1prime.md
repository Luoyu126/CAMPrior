# 路线 1'：以 DSBM 为核心的两模型交替薛定谔桥（实验方案，2026-11-28）

状态：方案，待用户确认后实现。没有任何实验在跑。

## 0. 目标与用户 11-28 的决定

- **目标**：跳出"一轮监督学习"的范式，直接用薛定谔桥的迭代训练。两个模型：
  - 生成方向（起点 → 终点）：从均匀 Bernoulli(0.5) 出发，生成独立集；
  - 加噪方向（终点 → 起点）：从终点分布出发，走回均匀分布。
  
  两者按 DSBM 交替训练。终点分布依次尝试单标签、多标签、多标签 + 局部扰动（按能量加权）等。
- **以 DSBM 为核心，不用 DSB**（§1）。
- **判断依据是实际训练中出现的现象，不是理论极限。** 理论上 DSBM 在有限标签终点下收敛到路线 1 的闭式薛定谔桥，但近似误差、迭代轮数和训练动态都可能让结果不同。所以每一轮都要记录，看实际走向。
- **网络架构完全沿用之前的 DIFUSCO**：`EncodeProcessDecode`，宽 64、8 层，**不输入时间 t**。理由（用户 11-28）：在 MIS 上，认为扩散本身不是关键，起作用的是"网络给出朝更好解的方向（相当于一步梯度上升），再做一次随机扰动（renoise 做的事）"。这件事不需要知道当前是第几步，所以不带 t。
  - 补充（11-28 核对）：每一步的转移由采样器按参考过程的信号 a_k 显式计算，时间不靠网络；网络只预测终点，而噪声水平基本能从状态本身读出来（节点多，冲突边比例等随 k 变化很确定）。所以预测终点的 DSBM 并不比 SL 更需要时间输入。只有"网络直接输出每步翻转概率"的写法才必须带时间，这不是本方案的写法。

## 1. 为什么选 DSBM 而不是 DSB

两者都用两个网络交替训练、迭代多轮，区别在每一轮怎么造训练数据：

- **DSB**（De Bortoli 等 2021，arXiv 2106.01357，算法 1，`ref/lit_pdfs/2106.01357.txt` 第 405–432 行）：用对方网络模拟整条轨迹（存下所有中间状态），训练自己把轨迹倒着走。
- **DSBM**（Shi 等 2023，arXiv 2303.16852，算法 1）：用对方网络只生成两端配对 (z, y)，中间状态用参考过程的桥在 z、y 之间重新抽，然后做 bridge matching。

DSBM 原文的对比（`ref/lit_pdfs/2303.16852.txt`）：
- 二维数据上 W2 全部优于 DSB（第 475–478 行，例如 moons 0.140 对 0.190、scurve 0.140 对 0.272）；
- MNIST ↔ EMNIST 上 **DSB 越训越差**：10 轮未收敛，30 轮后样本质量很差；DSBM 训到 50 轮仍在改善，运行时间少约 30%（第 544–548 行，附录第 2159–2164 行）；
- 原因（附录 F，第 1851–1889 行）：DSB 的误差逐轮累积，中间路径偏离参考过程（"遗忘参考桥"）；DSBM 每轮用参考桥重画中间路径，相当于每轮把这个偏差清零。

离散空间的 CSBM（arXiv 2502.01416）、DDSBM（arXiv 2410.01500）也都是 DSBM 这一类（`docs/20261125/math_route1.md` §12）。保留：上述对比来自 DSBM 自己的论文，且在连续空间。

## 2. 方法

### 2.1 参考过程：两端相关（a_N > 0）

- 参考过程是固定的逐位对称翻转链：从解 y（k = 0）走 N = 50 步到噪声端，走完后每个节点与出发时相同的概率为 (1 + a_N)/2。
  - a_N = 0：噪声端与解完全无关（memoryless，DIFUSCO 的设定）。
  - a_N > 0：两端相关。ω = log((1 + a_N)/(1 − a_N))；ω = 0.35 时每个节点总翻转概率约 41%，终点与解约 59% 的节点相同。
- **a_N = 0 时薛定谔桥的配对就是独立配对**（`math_route1.md` 命题 6.1：配对 ∝ g_m · exp(2ω · 重合数)，ω = 0 时指数项消失），理论上 DSBM 会退回普通 SL。所以**主方案用 ω > 0**；ω = 0 只作对照，用来分离"迭代自生成配对"本身的作用。
- 薛定谔桥把"噪声端是均匀分布"作为约束强加，参考过程不必走到均匀；这也是 DSB 原文"少步数"的来源（第 74–75 行），ASBS 去掉 memoryless 限制的出发点（`ref/papers/asbs.txt` 第 26、153、259 行）。

### 2.2 两个网络（结构都是 DIFUSCO 的 `EncodeProcessDecode`，不带时间）

- **生成网络 G**（就是现有的 SB-DIFUSCO）：输入 x_k，输出每个节点属于解的概率；采样用 renoise（以起点为一端的桥）或后验。
- **加噪网络 N**（就是 1D 的 `--sb_reverse`）：输入 x_k，输出每个节点的起点值概率；采样同理，方向相反。
- 损失：对缓存配对的软目标交叉熵（1D 已实现：给定 x_k，在该图缓存的配对上算精确后验作目标）。

### 2.3 一轮迭代（沿用 1D 的流水线 `experiments/20261125_sbdifusco_rbsmall_imf/run_imf.sh`）

1. **采样**：
   - G 从均匀起点 z ~ π_A 出发，在每张训练图上采 J 条链，得到配对 (z, ŷ)，写给 N 当训练数据；
   - N 从终点 y ~ π_B 出发采 J 条链，得到 (ẑ, y)，写给 G 当训练数据。
2. **训练**：G、N 各自在对方给的配对上做 bridge matching，训练 E 个 epoch，接着上一轮的参数。
3. 两个方向每轮都用对方上一轮冻结的参数生成数据（1D 的"交叉喂入"），等价于两条交替的 DSBM 链（`math_route1.md` §12.4），不违反 DSB 第 395–397 行"不能同时更新"的提醒。

两处要定的细节，默认取 1D 的做法：
- **G 生成的 ŷ 是否先贪心解码成合法独立集再交给 N**：默认解码（1D 如此，π_B 也只支撑在合法解上）。严格的 DSBM 应直接用模型样本；作为 §3 D2 的一个对照。
- **每轮学习率**：每轮重新走一遍余弦调度（1D 如此）。

### 2.4 初始化

- **IMF 初始化**（DSBM-IMF）：第 0 轮的配对是独立配对，z ~ π_A，y ~ π_B。G 从 SL 检查点出发（1D 用 11-19 的 400 epoch KaMIS 多解软目标模型）。
- **IPF 初始化**（DSBM-IPF，DSBM 命题 10）：第 0 轮的配对取参考过程的两端，y ~ π_B，z ~ 参考过程从 y 走到噪声端。ω > 0 时与独立配对不同。

## 3. 实验

### D0 流水线检查（半天）

### D1 主实验：多标签（KaMIS 多解，每图约 42 个），ω = 0.35，IMF 初始化，L = 10 轮

同时跑三个对照，都是 10 轮、同样的 epoch 数和学习率重启：

| run | 配对怎么来 | 用途 |
|---|---|---|
| **DSBM ω = 0.35** | 每轮由对方网络生成 | 主方法 |
| DSBM ω = 0 | 每轮由对方网络生成，但参考过程 memoryless | 分离"迭代自生成配对"与"就近配对" |
| 冻结配对 ω = 0.35 | 每轮重新抽闭式 Sinkhorn 配对，不用网络 | 同训练量的路线 1（排除"多训了几轮"的混杂，1D 就有这个问题） |

### D4 换终点分布（每一步看前一步结论再做）

| 终点 π_B | 来源 | 看什么 |
|---|---|---|
| 单标签 | KaMIS 单解 | 配对没有内容，理论上 DSBM 不应带来变化；看实际迭代会不会变差或变好 |
| 更多最优解 | k128（每图 66.9 个）、plateau256（每图约 232 个） | 阶段 E 观察到最优解越多，就近配对相对独立配对越有利（+0.02 到 +0.04） |
| 多标签 + 局部扰动，按能量加权 | 新工具（§5 任务 4）：从 KaMIS 解出发跑 Metropolis 链（加点、删点、交换），只在离 KaMIS 解 Hamming 距离 ≤ r 的独立集内游走，平稳分布 ∝ exp(\|s\|/T)；每图存 M 个样本 | 用户最初的想法；阶段 E 的"踢 + 局部搜索"在 SL 下有害（−0.05 到 −0.09），看 DSBM 下结论是否改变 |
| KaMIS + DiffUCO 打磨解 | 阶段 E 的 `k128diffuco` | 阶段 E 单种子最好（19.991），作为参照 |

r、T、M 待用户定。建议起点：r = 6（阶段 E 的踢动平均离最优解约 4.3），T ∈ {0.5, 1}，M = 128。

## 4. 指标（每一轮都记录）

按 `docs/related_work_eval.md` §3、§5（MIS 领域报优化指标；用户 11-06 定 MIS 大小为主）：

- **主指标**：验证锚点（验证图第 64–499 张）best-of-20 MIS，renoise 50 / 10 / 5 步、后验 50 步，评测种子 0。每轮对 G 的最后一个 epoch 评测（只用验证集前 64 张图选 epoch 的 best.pt 会混入选择噪声，所以主曲线用固定 epoch，best.pt 另报）。
- **训练动态**（这次的重点）：
  - 两个缓存配对的平均 Hamming 代价，与闭式 Sinkhorn 配对比；
  - 起点依赖比值（同一起点两条链终点的距离比；独立配对约 1.00，路线 1 约 0.965）；
  - G 的终点分布：样本中属于标签集合的比例、到最近标签的 Hamming 距离、按最近标签归类后的频率与 π_B 的总变差；
  - N 的终点是否像均匀分布：选中密度、冲突边比例、与出发解的一致率（与 Shengyu SBPD 的 `ber_gap` 同一组统计）。
- 测试集只在判定"有用"并用第二个种子确认之后才看。

## 5. 预先定的判定

- **DSBM 有用**：D1 中 DSBM ω = 0.35 在某一轮（预先定为最后一轮，L = 10；另报全部曲线）比"冻结配对 ω = 0.35"和"冻结配对 ω = 0"都高，锚点 50 步或 10 步逐图配对差的 95% 区间不含 0；再用第二个种子确认。
- **迭代本身的作用**：DSBM ω = 0 − 冻结配对 ω = 0。
- **就近配对在迭代下的作用**：DSBM ω = 0.35 − DSBM ω = 0。
- 单种子差在 0.03 以内不下结论（1C 种子间差约 ±0.02）。
- 若出现"越迭代越差"（DSB 在 MNIST 上的现象），记录发生在第几轮、哪些训练动态指标先变坏，作为结果之一。

## 6. 实现任务（每项一个提交）

1. 加噪网络采样时按 π_B 的权重抽起始的解（现在 `CAM_SB_STARTS` 在标签集合内均匀抽）。
2. `imf_cache.py` 加 IPF 初始化模式：y ~ π_B，z 从参考过程走到噪声端。
3. 迭代脚本：每轮结束自动在锚点上评测 G，记录 §4 的训练动态指标；支持 L = 10、冻结配对对照、ω = 0。
4. 扰动终点的 MCMC 采样工具（§3 D4），输出与现有标签集合相同的格式。
5. N 的终点统计（密度、冲突边、一致率）。

## 7. 风险

- **照搬文献**：DSBM 的优势是连续空间上、作者自己报告的；离散 MIS 上没有直接证据。1D 跑了 3 轮，与闭式配对打平；这次多跑轮数、换终点，也可能仍然打平。
- **自生成配对的偏差**：G 生成的 ŷ 经贪心解码后不一定在 π_B 的支撑上（1D 中 G 自己生成的配对代价比闭式高 5.1%）。迭代可能把配对推向"模型容易生成的解"，而不是 π_B。这也可能正是有益的方向（"好学的解"），要靠 §4 的终点分布指标区分。
- **误差累积**：DSBM 比 DSB 好，但仍可能逐轮退化；有每轮评测，可以及时发现。
- **成本**：每个 run 每轮约 1 小时、2 张卡；D1 约 12 小时，D2–D4 视结果而定。
- **不带时间输入**：依据是用户对 MIS 上扩散作用的判断（§0）。如果 DSBM 效果不理想，可作为排查项：G、N 与 SL 对照同时换成带时间的版本。
