# 20261125_sbdifusco_rbsmall：路线 1，薛定谔桥配对的 DIFUSCO（RB-small MIS）

依据：`docs/20261125/plan.md` 阶段 1B–1F；数学：`docs/20261125/math_route1.md`；进度：`docs/20261125/status.md`。

## 目的

在 KaMIS 多解标签（`matched_kamis_loaderorder.pt`，每图约 42 个）上，比较独立配对（基线）与薛定谔桥配对（起点 Bernoulli(0.5)^n，"就近"配对，强度 ω）训练出的 DIFUSCO。

## 配置

与基线 `20261119_difusco_rbsmall_reach` 的 `q5_mkamisfix_long{,_soft}` 相同：50 个扩散步、余弦噪声表、400 epoch、每步 40 张图、AdamW 2e-4、checkpoint 按前 64 张验证图选。

- `launch.sh <gpu> <mode> [seed]`：训练。
- `evaluate.sh <gpu> <run dir> <anchor|test> <sampler> <steps> <seed>`：评测。`anchor` 是验证锚点（验证图按加载顺序的第 64–499 张，共 436 张，`/usr0/home/shengyuf/yunyi/data/rb_small_valanchor` 是指向原文件的符号链接）。选配置只看锚点。

### 训练配置的混杂（1B 标准 4）

ω = 0 的 SB 代码路径在数学上就是独立配对软目标（1B 标准 2：200 步损失逐步相同），但单卡训练的它比多卡训练的基线高 +0.044 [+0.006, +0.081]（50 步，逐图配对，两个基线种子合并）。所以 1C 对原基线的"提升"大部分来自训练配置。为此补跑：单卡的原代码路径独立配对软目标（种子 0，检验标准 4 的配置对齐版本）和单卡 ω = 0 种子 1（作为配置一致的基线）。

### ω 的选择

ω = 0.35（两个种子 50 步均值 19.967）；0.5 打平（19.951，各步数都是中性）；1.0 更差（19.910，50 步 −0.057 [−0.089, −0.024]）。

（ω 只按 50 步均值选；下面的判定不再用于选择。）

- **主结论（配置一致的 ω = 0 基线）：中性。** 选定的 ω = 0.35 在 50 步和 10 步都在 ±0.03 以内，两种采样器一致；阳性条件（50 步 ≥ +0.03 或 10 步 ≥ +0.05，且区间不含 0）不满足。没有触发阴性分支，1D、1E 照常进行。
- 对原基线是阳性（+0.047），但 ω = 0（数学上与原基线相同，只是单卡训练）本身就比原基线高 +0.039，所以这部分"提升"来自训练配置，不来自 SB。以哪个为准见 `docs/20261125/status.md` 的"待用户确认"。
- 5 步时 ω = 0.35、0.5 比 ω = 0 好 +0.05 到 +0.07（区间不含 0），即 SB 配对在极少步数时有帮助；plan 的判定不看 5 步，这里只作记录。
- ω = 1.0 在 50 步明显更差。

### 起点决定解的程度（成对追踪，评测种子 100，50 步）

d_same：同一个 x0 跑两次得到的两个解的平均 Hamming 距离；d_diff：不同 x0；ratio = d_same / d_diff。hit：解落在"与 x0 重合最多的 KaMIS 标签"附近的比例（val64，KaMIS 多解 k128），hit_shuf 是把起点打乱后的同一指标。两个种子的平均：

| 模型 | ratio 锚点 renoise | ratio 锚点 posterior | hit val64 renoise（打乱） |
|---|---|---|---|
| 原基线（4 个 run） | 1.001 | 1.002 | 0.149（0.149） |
| ω = 0 | 0.998 | 1.001 | 0.141（0.143） |
| ω = 0.35 | 0.968 | 0.978 | 0.167（0.145） |
| ω = 0.5 | 0.945 | 0.962 | 0.180（0.152） |
| ω = 1.0 | 0.873 | 0.920 | 0.195（0.156） |

- 独立配对（原基线、ω = 0）的比值都接近 1，符合预期。
- 比值随 ω 单调下降、hit 随 ω 单调上升：模型确实学到了"起点 → 解"的就近对应，ω 越大越强。
- 但 MIS 大小并不随之变好（ω = 1.0 反而更差）：在 50 步、20 个样本取最好的协议下，起点依赖本身不带来更好的解。
