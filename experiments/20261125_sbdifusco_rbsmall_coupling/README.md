# 20261125_sbdifusco_rbsmall_coupling：真实标签上的薛定谔桥配对分析（阶段 1A）

依据：`docs/20261125/plan.md` 1A；数学：`docs/20261125/math_route1.md` §2、§7。不训练模型。

## 目的

在 RB-small 的训练图上，用 KaMIS 多解（`matched_kamis_loaderorder.pt`，每图平均 43 个、中位数 27 个解）计算起点 Bernoulli(0.5)^n 与标签集之间的静态 SB 配对，回答三个问题：

1. 蒙特卡洛 Sinkhorn 要多少个起点 K，标签边缘的相对误差才 < 2%？全部 4000 张图预计算要多久？
2. 不同强度 ω 下，每个起点实际分到几个标签（有效标签数）？据此给 1C 选 3–4 个 ω。
3. SB 配对比独立配对把起点和标签拉近了多少（平均 Hamming 代价）？

## 配置

- 200 张训练图：4000 张中按种子 0 随机抽取。其中 30 张只有 1 个解、3 张有 2 个，有效标签数的统计只用 M ≥ 3 的 167 张。
- ω ∈ {0.05, 0.1, 0.2, 0.35, 0.5, 1.0}，a_T = tanh(ω/2)，π1 在每张图的标签上均匀。
- 求解：`cam/scripts/sb/coupling_analysis.py`，GPU 上 float32，起点只保存到标签的距离。在样本上迭代到最大相对误差 < 1e-4。
  - 前 3 张图上与 float64 的 `utils/sb_coupling.sinkhorn` 对照：log g 相差 < 2e-4，即 float32 的停止容差。
- 误差测量：用新抽的起点计算配对的标签边缘，记录 max_m |边缘_m − π1(m)| / π1(m)。主表用 2^22 个新起点，ω = 1 补跑用 2^24 个。
  - 同时报告测量本身的噪声下限：2 倍标准误 / π1，取各标签中的最大值。
- 有效标签数：每个起点 z 上 1 / Σ_m π*(m | z)^2，对新起点取平均。
- GPU：主表和补跑各用 4 张卡（GPU 0–3），各约 10 分钟。
- 启动：`launch.sh main 0 1 2 3`；`launch.sh omega1 0 1 2 3`。输出在 `runs/experiments/20261125_sbdifusco_rbsmall_coupling/`：`coupling_stats_<分片>.jsonl`、`coupling_stats_w1_<分片>.jsonl`。主表的日志名为 `shard_<分片>.log`，是改名前的启动产生的。

- 独立配对的平均 Hamming 代价恒为 n/2：均匀起点与任何标签的期望距离都是 n/2。
- SB 配对只能利用起点的随机涨落。一个约 20 个点的解与随机起点重合约 10 ± 2.2 个点，所以代价最多只降低几个百分点。ω = 1 时平均距离少 5.3 位，相当于起点与所配标签的重合点数平均多了约 2.7 个。这就是 SB 模型要学到的"就近"信号的量级。
- ω ≤ 0.2 时有效标签数高于标签数的 70%，配对与独立配对几乎没有区别。

## 结论（对照 plan.md 1A 的验收标准）

1. **蒙特卡洛精度与耗时**：K = 2^22 时所有 ω 的标签边缘最大相对误差 ≤ 1.10%（< 2%）；全部 4000 张图预计算最多 18.3 分钟（< 1 小时，单卡）。**通过**。
2. **给 1C 的 ω**：取 **ω ∈ {0.35, 0.5, 1.0}**。三者的有效标签数中位数（18.3、11.7、4.1）都在 1.5 到标签数一半之间，按图计分别有 62%、80%、92% 的图落在这个范围。ω ≤ 0.2 不选，因为有效标签数超过标签数的 70%。
3. **阴性出口没有触发**：ω ≥ 0.35 时只有 ≤ 7% 的图有效标签数高于 80%。

提醒：SB 配对带来的"就近"信号本身很弱（第 2 节），这是 1C 结果可能是中性的一个先验原因。
