# 2C：跨图共享的 DASBS 在 RB-small 上训练

依据 `docs/20261125/plan.md` 的 2C。代码 `cam/solvers/dasbs.py`，数学见 `docs/20261125/math_route2.md`，逐轮过程见 `docs/20261125/status.md`。

主指标是验证锚点（验证图第 64–499 张，436 张）上的 MIS 大小（20 条链取最好，贪心解码最后一步的概率）。总变差、原始终点的可行比例只当诊断。

## 设置

- `launch.sh <gpu> <mode> [seed]`：训练。设置向 DiffUCO RB-small 看齐，见脚本头部（网络宽 64、8 层，每次参数更新 40 张图 × 10 条链，每 epoch 100 次更新，RAdam 1e-3，梯度范数裁剪 1，余弦衰减，β = 1.2，400 epoch）。
  - 模式：`sb_a<α>`（log-linear 参考过程 γ = 1，带修正项，每阶段 200 次控制器 + 100 次修正项，完整的 SB）；`ml`（memoryless，α = 0，不用修正项，没有 SB 的离散 adjoint matching）。
  - 环境变量：`TEMP`、`TAU0`、`TAU1`、`N_ANNEAL`、`EPOCHS`、`OVERFLOW`（`rescale` 或 `skip`）、`TAG`（run 名后缀）。
- `evaluate.sh <gpu> <run dir> <mode> <anchor|test> <steps> <seed>`：评测 best.pt（`CKPT=epoch_XXXX` 评测中间 checkpoint，用于训练效率曲线）。同时记录采样器原始终点的可行比例、大小、冲突数。

## 验收标准（plan.md 2C）

- 跑通：验证锚点上 ≥ 19.5。达不到时允许 2 轮诊断（合计最多 40 GPU 小时）。
- 有竞争力：≥ 19.85。
- SB 是否有用：sb − ml 逐图配对差 ≥ +0.03 且区间不含 0 为阳性。
- 另报训练效率曲线。

- τ < 1 以后被跳过的控制器批次越来越多（ml 种子 0：epoch 60–100 的 4000 个批次跳过了 3995 个），训练停住；验证集前 64 张图的 MIS 一直在 17.3–17.7。
- 原因：只要批次里有一个元素的梯度超过 1e30（对数比值约 69），整个批次就被跳过；RB-small 上对数比值可到 84/τ。

### 为什么不截断标签

`cam/scripts/sb/dasbs_clip_effect.py`：在小图（`data/sb_small/test` 前 8 张，n ≤ 12，β = 1.2）上精确计算"截断后的不动点" E[min(ξ, e^L) | x_t] 驱动的采样器终点分布，与未截断的精确 SB 比较。未截断的场与 ExactBridge 的精确控制器一致（误差 2e-14）。8 张图的平均（`runs/experiments/20261125_dasbs_rbsmall/clip_effect/summary.txt`），50 步，α = 0.5：

| τ | 最大对数比值 | 截断 L | 贪心解码 MIS 期望（目标） | 可行概率 |
|---|---|---|---|---|
| 0.3 | 18 | 不截断 / 20 / 30 / 60 | 5.232（5.230），四者相同 | 0.697 |
| 0.1 | 53 | 不截断 | 5.375（5.375） | 0.924 |
| 0.1 | 53 | 20 | 5.229 | 0.454 |
| 0.1 | 53 | 30 | 5.375 | 0.803 |
| 0.05 | 106 | 不截断 | 5.375（5.375） | 0.987 |
| 0.05 | 106 | 20 | 4.938 | 0.108 |
| 0.05 | 106 | 30 | 5.229 | 0.491 |
| 0.05 | 106 | 60 | 5.375 | 0.858 |

截断只要低于最大对数比值就有明显偏差（α = 0 的结果相同）。原因：低温下 E[ξ | x_t] 主要来自"离低能状态差一位"的少数终点，它们的 ξ 极大；截断和整批跳过去掉的恰好是这部分。RB-small 上对数比值到 84/τ ≈ 1700（τ = 0.05），没有可用的截断值。

## 第 1 轮（溢出批次整体缩放）：失败

- 修复：`--dasbs_rescale_overflow`。溢出批次的逐元素梯度在对数空间算出后整体除以同一个正常数；有梯度范数裁剪 1 时，优化器收到的更新与精确算术完全相同（测试 `test_rescaled_overflow_update_is_exact`）。
- 结果：需要缩放的批次很少（快速诊断 ml 到 epoch 56 共 47/5700），但 MIS 不上升：快速诊断 ml（τ 用 60 epoch 退到 0.05）epoch 55（τ = 0.13）锚点 10 步 17.351，初始网络 17.541。原始终点约 127/253 个点被选、约 700–1400 条冲突边，与 Bernoulli(0.5) 相同。
- 探针 `cam/scripts/sb/dasbs_probe.py`：控制器对所有位（已选、未选）都预测 log Φ ≈ 50–340，每步每位的翻转概率都是 1，状态在 x 与 1 − x 之间来回跳。这是在线 ctrl-AM 的一个自洽的退化不动点：终点随机时 P(x1_i = 1 | x_t) ≈ 0.5，已选位的目标比值约 e^88，所以 E[ξ_i | x_t] 对每一位都很大，采样器保持随机。全长 ml 在 epoch 30（τ = 0.9）就已如此（未选位预测 log Φ ≈ 10，目标平均 −10）。
- 根本原因：温度尺度。RB-small 平均度约 37，随机状态下 |ΔH| 平均 21.0（中位数 20.6，90% 分位 33.8），τ = 1 时比值已到 e^28，对这些图并不"热"。2B 的小图度数 ≤ 11，所以没遇到。
- `runs/experiments/20261125_dasbs_rbsmall/*_round1/`。

## 第 2 轮（最后一轮）：τ 从 20 几何退火到 0.05

- `--temp_schedule geometric`，τ = 20 · (0.05/20)^(epoch/300)，之后保持 0.05。τ0 = 20 是随机状态下 |ΔH| 的平均值，使起始比值约 e^(±1)。其余设置不变。
- run：ml、sb（α = 0.5）种子 0，400 epoch；快速诊断各一个（80 epoch 退火，共 100 epoch）。
- 快速诊断 ml（11-26 01:00 前后的探针，`dasbs_probe.py`，锚点第 1 张图，20 条链，10 步）：

  - 高温起步之后，采样器先是一路变好：τ 从 20 降到 2 的过程中终点从随机状态变成接近可行（约 20 个点、10 条冲突边，这张图的 KaMIS 解约 20–21）。
  - 在 τ ≈ 2 时原始权重在一两个 epoch 内突然失去对输入的依赖（参数范数没有变大，约 20），随后输出一个对所有点都很大的常数，采样器回到随机，并且再也回不来（随机终点上的目标比值约 e^(±11/τ)，退化态是吸收态）。所以第 1 轮看到的退化，主要原因是一次优化上的崩溃加上在线训练的正反馈，而不只是起始温度。
  - 快速诊断 ml 的退化已确定，停掉（epoch 42）；快速诊断 sb 继续。全长 run 退火慢 3.75 倍，约 epoch 115 到 τ = 2，那时看它们是否同样崩溃。
  - 按规则第 2 轮是最后一轮，不再改配置；如果全长 run 也崩溃，本阶段记为失败，并把"崩溃机制"和建议（例如 DASBS 附录 C 的样本缓冲区、低温时更小的学习率）写进报告。
